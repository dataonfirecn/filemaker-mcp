# StarRC Web 零件六业务权限规划

版本：1.1（2026-07-27，增加模块级精细权限）  
范围：FileMaker「零件」布局中的采购、业务、设计、品检、仓库、雷雕六个入口，以及 StarRC Web 对应的账号、页面、接口、字段、动作和数据范围权限。

## 1. 结论

Web 端应新增六个彼此独立的零件业务权限组：

1. `part.procurement`：采购
2. `part.business`：业务
3. `part.design`：设计
4. `part.quality`：品检
5. `part.warehouse`：仓库
6. `part.laser`：雷雕

每个组不能只做“显示/隐藏页签”一个布尔值，还必须至少区分：

- `none`：无权访问
- `read`：可查看
- `edit`：可修改本组负责的字段、可新增本组记录或附件
- `approve`：包含 `edit`，并可审核、特采、库存调整确认等高风险动作
- `export`：独立开关，不随 `read/edit/approve` 自动开放
- `recordScope`：记录范围，默认 `all`；需要时限制到样品、仓库、部门或指定客户

这些等级只作为管理员快速套用的角色模板。后台最终授权不能只判断
`read/edit/approve`，而要判断到“组 → 模块 → 动作”，例如：

- `part.procurement.cost.read`
- `part.procurement.cost.approve`
- `part.design.drawings2d.downloadOriginal`
- `part.quality.specialAcceptance.approve`
- `part.warehouse.adjustment.approve`
- `part.laser.outputFiles.publish`

六个权限组只负责零件业务域。现有产品、订单、BOM、自然语言查询、RAG 和账号管理权限继续保留，不应混入这六个组。

当前实现不能满足要求，原因有三项：

1. `/api/part-directory`、`/api/part-assets`、`/api/part-creation` 等零件接口目前全部归到 `canViewBom`，无法独立控制六个入口。
2. 当前权限对象只有 9 个粗粒度布尔值，没有采购、业务、设计、品检、仓库、雷雕的独立权限。
3. `canViewPrice` 把销售价、采购成本、订单金额、库存货值混成一个权限。FileMaker 采购布局明确包含采购成本和询价，但采购账号当前 `canViewPrice=false`；继续沿用会错误屏蔽采购必需资料。

因此，本次不能只在前端增加六个菜单开关，必须同时完成权限模型、后台接口、字段过滤、管理页面和测试。

本方案使用了以下资料：

- 2026-07-27 用户截图：确认零件布局顶层存在采购、业务、设计、品检、仓库、雷雕六个入口。
- 2026-07-27 FileMaker Data API 实时布局元数据：核对六套部门布局的字段、值列表、关联字段和 portal。
- 2026-07-24 FileMaker「管理安全性」只读盘点：97 个账号、39 个权限集、15 个扩展权限。
- StarRC 当前 PostgreSQL 权限同步结果：核对相关权限集的账号数、启用数和 Web 权限。
- 当前 StarRC 前后端代码：核对现有权限键、路由保护方式和零件详情原型。

确认状态分为：

- **已核实**：来自 FileMaker 实时元数据、安全性盘点或当前数据库。
- **目标规则**：本方案建议在 Web 端实施的权限。
- **上线前复核**：需要部门负责人确认的业务边界，不应由技术人员自行猜测。

## 4. FileMaker 当前安全性约定

### 4.1 已核实的原生约定

- `[完全访问权限]` 和 `Master` 为管理权限。
- `業務部`、`業務經理` 能访问客户价或贸易价格资料。
- `設計部`、采购、仓库权限集不能访问专门的客户价格表和贸易价格表。
- 普通员工权限集当前没有 `fmrest` 或 `fmodata`；这两个扩展权限只给完全访问权限，是正确方向。
- `fmapp` 和 `fmwebdirect` 对多数在用权限集开放。生产、仓库、包装等不使用 WebDirect 的账号应关闭 `fmwebdirect`。
- 多数自定义权限集允许执行全部脚本，部分还允许打印和导出。这一约定过宽，Web 端不能照搬。
- 已抽查到业务权限集对 `ProductPrice::price` 有修改能力。Web 必须把“查看销售价”和“维护销售价”拆开。
- `INDEX` 表包含批次价格、货值等财务字段；即使部门不能进入专用价格表，也可能通过关联字段或原始布局间接看到财务数据。

### 4.2 六组与现有 StarRC 粗粒度权限的对应

| FileMaker 权限集 | 当前 StarRC 主要权限 | 当前问题 |
|---|---|---|
| `業務部` | 产品、订单、库存、BOM、价格；不可合并订单 | 可访问业务资料，但零件业务页没有独立业务权限 |
| `業務經理` | 同业务部，另可合并订单 | 经理级审核、导出、价格维护仍未拆分 |
| `設計部` / `設計部_只讀` | 产品、BOM；无订单、库存、价格 | 两者当前 Web 策略相同，未体现“可编辑/只读”差异 |
| 三个采购权限集 | 产品、库存、BOM；无订单、销售价格 | 一般、信任、样品信任当前 Web 策略相同 |
| 四个品检权限集 | 产品、订单、库存；`canViewBom=false` | 零件接口当前要求 `canViewBom`，因此品检账号反而会被零件页拒绝 |
| `倉庫_組員` / `倉庫_組長` | 产品、订单、库存、BOM；无价格 | 组员与组长当前 Web 策略相同，未体现库存调整审批差异 |
| `Laser` | 产品、BOM；无订单、库存、价格、问答 | 可进入零件域，但没有独立雷雕字段权限 |

### 4.3 必须修复的 FileMaker 暴露点

1. `零件 資料_倉庫` 的 portal 元数据包含 `零件_產品_產品售價::Price`。仓库账号不应看到销售价，应在 FileMaker 字段权限和 Web 响应两层阻断。
2. `零件 資料_業務` 除产品售价外，还包含纸箱材料价格、说明书单价等包装成本字段。需要明确这些是业务报价资料还是采购成本，不能全部跟随一个 `canViewPrice`。
3. `零件 資料_採購` 包含单位成本、实际成本、内部估价、询价价格、供应商报价、库存货值、汇率和多种成本计算。采购需要其中一部分，但不应因此得到客户销售价或订单金额。
4. 所有部门布局中的关联 portal、打印布局、导出脚本和“全部脚本”权限都必须按同一字段规则复核，不能只检查页面上可见的主字段。

## 5. 六个入口的内容规划

以下内容按 Web 页面实际要展示的子页签整理。公共字段只展示一次；每个部门只能修改本部门负责的字段。

### 5.1 公共只读摘要

六个组只要有任一 `part.*` 权限，即可查看安全的公共摘要：

- 零件编号、内部名称、对外名称
- 零件品种、材料分类、材料规格、材料属性
- 生命周期、供应状况、审核状态
- 主图、受权限控制的缩略图
- 制造商名称的安全显示值
- 库存数量摘要是否显示，由 `part.warehouse` 或业务需要决定

公共摘要禁止包含：

- 销售价、采购成本、订单金额、库存货值
- 未授权客户名称和客户专属编号
- 原始 FileMaker `raw` 字段
- 永久 COS 地址
- 其他部门的内部备注、附件原文件和审批意见

### 5.2 采购组 `part.procurement`

FileMaker 布局已核实有 268 个字段对象、232 个唯一字段。

建议子页签：

1. **采购概览**
   - 制造商、询价厂商、外加工厂商
   - 采购员、供应状况、生产周期
   - 最低订购量、MOQ1/2/3
   - 已下单数量、建议下单数量、预计余量/欠料
   - 采购备注
2. **供应商与询价**
   - 第一/第二/第三供应商报价
   - 报价附件
   - 询价价格、询价厂商
   - 供应商规格书及修改人、修改日期
3. **成本核价**
   - 单位成本、实际成本、内部估价
   - 台币成本、汇率、台币转 RMB
   - 模具费、塑胶成本、线材成本、纸张/说明书成本
   - 库存货值只给信任级或更高权限
4. **采购记录**
   - 日期、记录明细、记录账号
   - 只允许追加；历史记录默认不可覆盖或删除
5. **库存参考**
   - 入库、出库、在库、批号、采购单 ID
   - 采购可读，库存数量修改归仓库组
6. **规格与品检参考**
   - 图面、规格书、材料、检查尺寸、公差、品检规范
   - 默认只读
7. **关联资料**
   - 关联产品、关联零件、生产流程 BOM、修改记录

采购组禁止：

- 客户销售价、贸易价、订单金额
- 客户专属财务资料
- 修改库存交易数量
- 修改设计图档、品检结论、雷雕参数
- 删除零件主记录或采购历史

### 5.3 业务组 `part.business`

FileMaker 布局已核实有 133 个字段对象、118 个唯一字段。

建议子页签：

1. **业务概览**
   - 零件编号、内部/对外/英文名称
   - 客户零件号、专属客户
   - 生命周期、供应状况、制造商、采购员
   - 业务内部备注、备件说明
2. **包装与对外资料**
   - 印刷 Logo、印刷车壳、彩盒、外纸箱、贴纸、说明书
   - 说明书规格、页数、数量、纸张计算
   - 客户图档
3. **销售价格**
   - 产品销售价和业务报价，只读或由独立价格维护权限控制
   - 业务普通账号默认只读；业务经理也不自动获得价格写入权
4. **关联产品**
   - 关联产品、关联零件、产品售价
   - 库存只显示摘要
5. **图片与业务附件**
   - 主图、打样图、包装图、客户图档
6. **流程参考**
   - 生产流程、品检流程名称、外加工注意事项
   - 默认只读

业务布局中已发现纸箱材料价格、说明书单价等字段。上线前要由业务和采购共同确认字段归属：

- 属于面向客户的包装报价：归 `salesPrice`
- 属于内部采购成本：归 `purchaseCost`
- 只是计算中间值：默认不返回浏览器

业务组禁止：

- 采购供应商底价、内部成本、库存货值
- 修改设计图纸、品检标准、库存流水和雷雕参数
- 删除零件和历史记录

### 5.4 设计组 `part.design`

   - 热处理条件、加工分类、外加工注意事项
4. **尺寸与公差**
   - A-L 检查尺寸
   - A-L 公差和第二公差
5. **生产流程**

   - 加工工艺流程 1-8

   - 设计可新增修改记录；已审核历史不可直接覆盖

- 销售价、采购成本、订单金额、库存货值
- 修改供应商报价、库存数量、品检审核结果、雷雕文件
- `設計部_只讀` 不允许上传、修改、审核或导出原图

### 5.5 品检组 `part.quality`

FileMaker 布局已核实有 155 个字段对象、124 个唯一字段，其中 65 个字段对象来自品检规范。

建议子页签：

1. **品检概览**
   - 零件编号、内部名称、材料、图面、半成品编号
   - 生命周期、审核状态、设计修改是否完成
2. **品检规范**
   - 品检规范、品检注意事项
   - 品检图注意事项 1/2
   - 品检规范审核状态
3. **尺寸与公差**
   - A-L 检查尺寸
   - A-L 公差及第二公差
4. **加工流程**
   - 零件加工流程 1-8
   - 加工工艺流程 1-8
5. **品检附件**
   - 品检文件容器 9-20
   - 品检图、主图和参考图
6. **特采与修改记录**
   - 特采日期、特采记录、特采品检记录、附件
   - 设计修改主题、内容、时间、部门
7. **BOM 与关联**
   - 品检产品 BOM、关联产品、库存摘要
8. **雷雕参考**
   - 雷雕参数、雷雕档、雷雕照片、美工档、治具
   - 默认只读

品检动作分级：

- `品檢員`：新增检查结果和附件；不能修改已批准的主规范或执行特采批准。
- `品檢主管`：可修改规范、审核和批准特采。
- `品檢包裝主管`：在主管权限上增加包装资料审核。
- `品檢包裝主管Excel`：在主管权限上增加受审计的导出。
- `包裝員`、`包裝員2部`：只读品检规范，另开放包装执行动作，不授予品检审核。

品检组禁止：

- 销售价、采购成本、订单金额、库存货值
- 修改库存流水、设计原图、供应商报价和雷雕主文件
- 删除品检历史、特采历史和审核记录

### 5.6 仓库组 `part.warehouse`

FileMaker 布局已核实有 99 个字段对象、86 个唯一字段。

建议子页签：

1. **库存概览**
   - 当前库存、安全库存、库存提醒
   - 仓库、主要位置、次要位置、仓库分工
   - 入库总和、出库总和、库存余额
2. **出入库记录**
   - 日期、批号、入库、出库、描述
   - 采购单 ID、内部编号、供货厂商、修改人
3. **欠料与补货参考**
   - 已下单数量、建议下单数量、预计欠料
   - 最低订购量、生产周期
4. **标签与作业**
   - 发料/收料标签
   - 库存提醒、盘点、位置调整
5. **图片与图面参考**
   - 主图、零件照片、打样图、外加工图
   - 默认只读
6. **关联产品与零件**
   - 产品、相关零件、BOM 位置
7. **品检/雷雕参考**
   - 已批准的品检规范、雷雕参数和作业图片
   - 默认只读

- 销售价、采购成本、订单金额、库存货值
- `零件_產品_產品售價::Price` 必须在后台响应中删除，即使 FileMaker portal 返回了它
- 修改设计、品检、采购和雷雕主数据
- 删除库存流水；冲销必须新增反向记录并保留原因

### 5.7 雷雕组 `part.laser`

   - 生命周期、供应状态、加工分类、审核状态
   - 主图和参考图
2. **雷雕参数**
   - `雷雕參數`
3. **雷雕文件**
   - `雷雕檔`
   - `雷雕美工檔`
4. **雷雕照片**
   - `雷雕照片`
5. **雷雕治具**
   - `雷雕製具`、`雷雕製具2`、`雷雕製具3`
6. **标签**
   - 发料/收料标签
7. **只读参考**
   - 制图员、采购员、开模厂商、客户代号/简称、零件备注

雷雕组禁止：

- 销售价、采购成本、订单金额、库存货值
- 修改零件名称、材料主数据、库存、品检标准、采购资料
- 删除已有雷雕版本；新文件应形成版本记录

## 6. 字段所有权

同一字段不能让多个部门无边界修改。建议所有权如下：

| 数据域 | 主责组 | 其他组 |
|---|---|---|
| 零件编号、内部名称、材料、规格、尺寸、设计图 | 设计 | 按需只读 |
| 对外/英文名称、客户零件号、包装和说明书 | 业务 | 设计、品检只读 |
| 供应商、MOQ、采购备注、采购成本、询价 | 采购 | 业务只读公开部分；其他无权 |
| 品检规范、检查尺寸/公差、检查附件、特采 | 品检 | 设计/采购/仓库按需只读 |
| 库存、位置、批号、出入库、盘点和标签 | 仓库 | 采购/业务按需只读 |
| 雷雕参数、美工档、雷雕档、照片、治具 | 雷雕 | 品检/仓库按需只读 |
| 销售价 | 业务价格维护角色 | 普通业务只读；其他无权 |
| 采购成本 | 采购信任角色 | 普通采购按业务确认只读；其他无权 |

任何跨组修改都必须通过明确的额外权限，而不是因为账号能看到另一个页签就可以修改。

## 7. 财务权限必须拆分

保留旧 `canViewPrice` 作为兼容入口，但新逻辑应拆成：

| 权限 | 含义 | 默认授权 |
|---|---|---|
| `finance.salesPrice.read` | 客户价、销售价、业务报价 | 业务、业务经理 |
| `finance.salesPrice.write` | 维护销售价 | 专门价格维护角色；默认不随业务经理开放 |
| `finance.purchaseCost.read` | 采购成本、询价、供应商报价 | 采购 |
| `finance.purchaseCost.write` | 维护采购成本和核价 | 采购信任角色 |
| `finance.orderAmount.read` | 订单金额、发货金额 | 业务及财务相关角色 |
| `finance.inventoryValue.read` | 库存货值 | 采购信任、财务或管理员；仓库默认无权 |

兼容迁移期间：

- 旧 `canViewPrice=true` 只可临时映射到 `salesPrice.read + orderAmount.read`。
- 不得自动映射到 `purchaseCost.write` 或 `inventoryValue.read`。
- 所有响应使用显式字段白名单，价格关键字过滤只作为第二道兜底。

## 8. 建议的权限数据结构

```json
{
  "schemaVersion": 3,
  "legacy": {
    "canViewProducts": true,
    "canViewOrders": false,
    "canViewBom": true
  },
  "partScopes": {
    "procurement": {
      "preset": "procurement_general",
      "modules": {
        "overview": ["read", "update"],
        "suppliers": ["read", "update"],
        "quotations": ["read", "create", "update", "submit"],
        "cost": ["read"],
        "purchaseHistory": ["read", "create"],
        "inventoryReference": ["read"]
      },
      "recordScope": {
        "type": "all"
      }
    },
    "business": { "preset": "none", "modules": {}, "recordScope": { "type": "all" } },
    "design": { "preset": "design_readonly", "modules": {}, "recordScope": { "type": "all" } },
    "quality": { "preset": "none", "modules": {}, "recordScope": { "type": "all" } },
    "warehouse": { "preset": "none", "modules": {}, "recordScope": { "type": "all" } },
    "laser": { "preset": "none", "modules": {}, "recordScope": { "type": "all" } }
  },
  "financialScopes": {
    "salesPrice": "none",
    "purchaseCost": "none",
    "orderAmount": "none",
    "inventoryValue": "none"
  }
}
```

规则：

- 权限集提供默认值。
- 账号覆盖只保存差异。
- `preset` 只负责快速生成模块动作，不参与后台最终判断。
- `approve` 不自动包含 `export`、批量操作或原文件下载。
- `read` 只表示可以读取模块安全字段，不表示能下载原文件。
- `update` 只允许更新模块写字段白名单，不能提交任意 FileMaker 字段。
- `export`、`downloadOriginal`、`bulkUpdate`、`reverse` 和 `publish` 均为独立高风险动作。
- 删除权限不包含在六组内，仅管理员或专门的数据治理流程可以执行。
- 旧会话每次请求继续检查当前策略版本；权限变化后下一次请求立即生效。
- 详细模块、动作和角色模板见第 17-24 节。

## 10. 后台接口规划

### 10.1 路由

建议保留当前零件列表接口，同时增加明确的部门视图：


现有 `/sections/procurement|specifications|quality|inventory|records` 可先做兼容适配，但最终页面与授权都应按六个部门视图组织。

### 10.2 后台强制规则

每个接口必须执行：

1. 验证会话和账号状态。
2. 读取账号的 FileMaker 权限集默认策略和账号增量覆盖。
3. 校验目标 `partScopes` 和动作等级。
4. 应用 `recordScope`。
5. 只查询该视图的字段白名单。
6. 根据 `financialScopes` 二次删除财务字段。
7. 对附件签发短时 COS URL；无权时不返回 `object_key` 和 URL。
8. 写操作只接受该组的可写字段；请求中多出的字段直接 403 或 422，不能静默写入。
9. 写入审计日志。

前端隐藏按钮只用于体验，不能作为安全控制。

### 10.3 代码改造点

- 扩展 `WebViewerPermissions`，支持 `partScopes` 和 `financialScopes`。

- 将 `dependencies._permission_for_request()` 中零件接口统一映射到 `canViewBom` 的逻辑替换为部门视图校验。

## 11. 前端页面规划

零件详情页顶层导航改成与 FileMaker 一致的六个入口：

```text
采购 | 业务 | 设计 | 品检 | 仓库 | 雷雕
```

规则：

- `none`：不显示页签；直接输入 URL 仍由后台返回 403。
- `read`：显示页签，不显示编辑、上传、审核和导出。
- `edit`：显示本组的编辑、上传、新增记录动作。
- `approve`：增加审核、特采、库存调整批准等按钮。
- `export=true`：显示导出按钮，导出的列也使用同一字段白名单。
- 一个账号拥有多个组时可同时看到多个页签，但每个页签保持独立权限。
- 页面不得请求所有部门资料后再在浏览器隐藏；只在打开获授权页签时按需请求对应接口。

当前零件详情原型的“概览、采购与成本、规格与标识、质量与流程、库存交易、关联记录、零件图库”是内容型页签，不能直接作为最终权限边界。应改为六个部门页签，每个部门内部再保留上述相关子页签。

## 17. 模块级精细权限模型

### 17.1 六层判断

每一次请求按以下六层判断，前一层不通过就立即拒绝：

1. **权限组**：采购、业务、设计、品检、仓库、雷雕。
2. **子模块**：例如采购成本、设计 2D 图、品检特采、仓库库存调整。
3. **动作**：查看、新增、编辑、提交、审核、导出、原件下载等。
4. **字段范围**：允许读取和写入哪些字段。
5. **记录范围**：允许处理哪些零件、仓库、客户、项目或样品。
6. **状态和归属**：草稿、已提交、已批准、已归档；本人创建或他人创建。

不能只因为用户有某个页面的查看权限，就允许他调用同页面的写入、导出或附件原件接口。

### 17.2 标准动作

| 动作编码 | 管理页面名称 | 含义 |
|---|---|---|
| `read` | 查看 | 读取模块的安全字段 |
| `create` | 新增 | 新增明细、申请、记录或草稿 |
| `update` | 编辑 | 修改允许字段，通常只限草稿 |
| `submit` | 提交 | 把草稿送审，提交后普通编辑者不可继续修改 |
| `approve` | 审核 | 批准或驳回；必须记录意见 |
| `publish` | 发布 | 把已批准的价格、图档、规范或参数设为正式版本 |
| `upload` | 上传附件 | 上传新文件或新版本 |
| `downloadOriginal` | 下载原件 | 下载 2D/3D、报价、品检或雷雕原文件 |
| `export` | 导出 | Excel/PDF/CSV 或批量下载 |
| `link` | 建立/解除关联 | 产品、零件、BOM、客户等关系 |
| `execute` | 执行业务动作 | 入库、出库、打印标签等 |
| `reverse` | 冲销/更正 | 对已执行流水生成反向记录；不是删除 |
| `bulkUpdate` | 批量操作 | 批量位置、批量审核、批量导出等 |

高风险动作 `approve`、`publish`、`downloadOriginal`、`export`、`reverse`、
`bulkUpdate` 不从 `update` 自动继承。

### 17.3 权限键命名

权限键统一使用：

```text
part.<权限组>.<子模块>.<动作>
```

示例：

```text
part.procurement.quotations.submit
part.procurement.cost.approve
part.business.salesPrice.publish
part.design.drawings2d.downloadOriginal

```

权限键一旦上线不得随意改名。页面名称可以调整，权限键保持稳定，避免历史审计和角色配置失效。

### 17.4 字段范围

每个模块配置两个版本化字段集：

- `readFieldSet`：后台允许查询和返回的字段。
- `writeFieldSet`：后台允许更新的字段，必须是 `readFieldSet` 的子集。

示例：

```json
{
  "module": "procurement.cost",
  "readFieldSet": "part_procurement_cost_read_v1",
  "writeFieldSet": "part_procurement_cost_write_v1"
}
```

管理员不在页面上逐个勾选 FileMaker 字段。字段集由代码/配置版本管理并经过测试，避免管理员误把
`INDEX::BATCHPRICE`、客户价、原始 ID 或计算中间字段开放给错误角色。

字段集变更必须：

- 代码审查或双人复核。
- 记录变更原因和版本。
- 自动运行“禁止字段不在响应中”的测试。
- 对旧角色自动使用新字段集，不需要逐账号修改。

### 17.5 记录范围

`recordScope` 至少支持：

| 类型 | 示例 | 用途 |
|---|---|---|
| `all` | 全部零件 | 部门需要处理全部零件 |
| `sample` | 样品/项目零件 | 采购样品信任权限 |
| `warehouse` | `五金仓、塑胶仓` | 仓库人员只管理指定仓库 |
| `department` | `包装部` | 部门专属作业 |
| `customer` | 指定客户 ID | 特定客户业务人员 |
| `project` | 指定项目 ID | 项目采购或设计 |
| `lifecycle` | 打样中、量产中 | 按零件阶段限制 |

角色授予的范围可以合并；账号上的限制条件在角色合并后再次收窄。账号停用、权限集停用和紧急拒绝为
硬性拒绝，不能被其他角色覆盖。

### 17.6 状态和归属

建议所有可审核资料使用统一状态：

```text
draft → submitted → approved/rejected → published → archived
```

规则：

- 普通编辑者只修改本人或本部门的 `draft`。
- `submitted` 后只能撤回或由审核者处理。
- `approved/published` 不直接覆盖，修改时创建新版本。
- 审核者原则上不能批准自己提交的高风险内容。
- 已发布价格、设计图、品检规范、雷雕参数和库存流水不可物理删除。

### 17.7 公共模块

公共模块不是第七个业务组，而是由任一六组权限派生的安全基础权限：

| 权限键 | 默认规则 |
|---|---|
| `part.common.summary.read` | 任一六组至少有一个模块 `read` 时开放 |
| `part.common.customer.read` | 业务组或明确的客户资料权限 |
| `part.common.stockSummary.read` | 采购、业务、仓库按需开放 |
| `part.common.auditTrail.read` | 主管或审计角色 |
| `part.common.thumbnail.read` | 任一六组可看安全缩略图 |
| `part.common.assetOriginal.downloadOriginal` | 不自动开放，跟随具体附件模块 |

### 18.2 采购高风险规则

- `cost.approve` 与 `quotations.approve` 应使用双人复核，提交人不能批准本人记录。
- 一般采购可以填报和提交报价，但不能把报价标记为正式核价。
- `inventoryReference` 永远不包含库存货值，除非另有
  `finance.inventoryValue.read`。
- 采购附件原件下载独立授权；预览不等于下载原件。
- 历史采购记录只允许新增更正记录，不允许覆盖或删除。
- 批量导出必须限制字段、行数、时间范围并记录导出原因。

### 18.3 采购字段所有权

采购可写：

- 采购员、供应状况、供应商、询价厂商、外加工厂商
- MOQ、最低订购量、生产周期、采购备注
- 采购报价和采购成本字段，按一般/信任级区分

采购只读：

- 零件名称、材料、规格、设计图、品检规范、库存流水

采购不可见：

- 客户销售价、贸易价、订单金额、客户财务资料

### 19.2 销售价工作流

建议将销售价从直接编辑改成：

```text
价格草稿 → 提交 → 审核 → 发布
```

- 业务人员和业务经理默认只能查看正式价格。
- 价格维护人员创建或修改价格草稿。
- 高风险价格由另一名价格审核人批准。
- 页面和 API 区分“当前正式价”和“待发布价”。
- 已发布价格不直接覆盖，必须形成新版本并保留生效时间。

### 19.3 包装价格字段

- 面向客户的包装报价：进入 `business.salesPrice`。
- 内部采购成本：进入 `procurement.cost`。
- 计算中间字段：只在服务器计算，不返回页面。

不能因为字段出现在业务布局，就默认业务人员可见或可改。

- 特采批准必须写原因、有效范围和有效期限。
- 特采不能自动修改正式品检规范。
- Excel 导出是独立权限，不因用户是主管就自动开放。

- 客户销售价
- 采购成本和供应商底价
- 订单金额
- 库存货值

品检需要判断来料供应商时，只返回供应商识别资料，不返回报价或成本字段。

### 22.2 库存动作规则

- 正常入库和出库是 `execute`，不是普通字段 `update`。
- 已执行流水不可编辑或删除。
- 错误流水使用 `reverse` 创建反向记录，并关联原流水。
- 组员可以申请库存调整，组长批准并执行。
- 组长不能批准本人创建的重大调整。
- 批量位置变更、批量盘点确认和批量标签打印单独授权。
- 仓库记录范围建议按 `warehouse_code` 限制；没有配置仓库范围时默认拒绝执行写动作。

### 22.3 仓库响应过滤

仓库模块即使通过关联产品查询到以下字段，也必须删除：

- `零件_產品_產品售價::Price`
- 客户价、贸易价
- 采购成本和供应商报价
- 订单金额
- 库存货值

库存数量与库存货值是不同权限；仓库可管理数量，不代表可查看货值。

## 24. 权限管理后台的精细化设计

### 24.1 管理对象

后台不建议把全部权限继续放在一个 JSON 编辑框中。应建立：

| 对象 | 用途 |
|---|---|
| 角色模板 | 采购一般、采购信任、设计只读、仓库组长等 |
| 模块权限 | 角色对具体模块允许哪些动作 |
| 账号角色 | 一个账号可以分配多个角色 |
| 数据范围 | 仓库、客户、样品、项目、生命周期 |
| 临时授权 | 起止时间，到期自动撤销 |
| 高风险附加角色 | 价格维护、原图下载、Excel 导出、批量操作 |
| 变更审批 | 高风险授权需要另一名管理员批准 |
| 权限审计 | 保存每次修改和有效权限快照 |

### 24.2 管理页面

账号详情页建议分五块：

1. **身份状态**
   - FileMaker 账号、权限集、启用状态、最近登录。
2. **角色模板**
   - 已分配角色、来源、有效期。
3. **六组模块**
   - 六张卡片；展开后显示模块和动作。
4. **数据范围**
   - 仓库、客户、样品、项目等限制。
5. **最终生效权限**
   - 显示合并后的有效权限、字段集版本和高风险动作。

必须提供“模拟检查”：

```text
账号 + 零件 + 模块 + 动作 → 允许/拒绝 + 原因
```

例如：

```text
Amy + se2018-00 + warehouse.adjustment.approve
结果：拒绝
原因：只有 warehouse_member；缺少 warehouse_leader
```

### 24.3 角色合并规则

推荐规则：

1. 默认全部拒绝。
2. 多个角色的允许动作做并集。
3. 账号数据范围限制在角色并集后再次收窄。
4. 财务、原件下载、导出和批量操作必须有显式授权。
5. 账号停用、权限集停用和紧急拒绝优先级最高。
6. 临时授权到期立即失效。
7. 不使用难以解释的大量“显式拒绝”规则，避免角色冲突。

### 24.4 建议的数据表

长期建议将角色和权限关系标准化，现有 JSONB 可作为迁移期配置或有效权限缓存：

```text
web_role
web_permission
web_role_permission
web_account_role
web_account_scope
web_permission_change_request
web_permission_change_log
```

关键字段：

- `web_permission.key`：稳定权限键。
- `web_permission.risk_level`：普通、敏感、高风险。
- `web_account_role.valid_from/valid_until`：临时授权。
- `web_account_scope.scope_type/scope_value`：数据范围。
- `web_permission_change_log.before/after/reason`：变更审计。

### 24.5 高风险授权

以下权限不能普通管理员单人直接赋予永久权限：

- 销售价发布
- 采购成本审核
- 库存货值查看
- 特采批准
- 库存调整批准和冲销
- 2D/3D、报价、品检、雷雕原文件批量下载
- Excel/CSV 批量导出
- 批量位置、批量关联和批量审核

建议要求：

- 填写原因。
- 另一名管理员批准。
- 默认设置有效期。
- 立即通知账号本人或部门负责人。
- 纳入月度高风险权限报表。

### 24.6 日常管理流程

#### 新员工

1. 选择一个基础角色模板。
2. 选择数据范围。
3. 高风险权限单独申请。
4. 预览最终生效权限。
5. 启用账号并记录审批。

#### 调岗

1. 先添加新岗位只读权限。
2. 完成交接后撤销旧岗位编辑和高风险权限。
3. 检查临时授权和原件下载权限。
4. 强制刷新会话。

#### 离职

1. 立即停用 Web 账号。
2. 关闭 FileMaker `fmapp/fmwebdirect`。
3. 撤销全部角色和临时授权。
4. 保留审计记录，不删除账号历史。

#### 定期复核

- 每月检查高风险权限和临时授权。
- 每季度由六部门负责人确认本部门角色和账号。
- 检查长期未登录账号、无使用角色和跨部门叠加权限。
- 检查导出、原件下载、特采和库存冲销记录。

### 24.7 模块级验收示例

| 场景 | 必须验证 |
|---|---|
| 一般采购提交报价 | 可提交，不可审核或导出采购成本 |
| 信任采购审核本人报价 | 拒绝，要求另一审核人 |
| 业务经理修改销售价 | 没有价格维护附加角色时拒绝 |
| 设计只读下载 3D 原件 | 只有预览权时拒绝 |
| 设计编辑覆盖已发布 2D 图 | 拒绝，要求上传新版本 |
| 品检员批准特采 | 拒绝 |
| 品检员修改本人草稿结果 | 允许 |
| 包装员审核品检规范 | 拒绝 |
| 仓库组员正常入库 | 在授权仓库范围内允许 |
| 仓库组员批准库存调整 | 拒绝 |
| 仓库组长批准本人重大调整 | 拒绝 |
| 仓库账号读取产品关联 | 响应不含销售价和货值 |
| 雷雕作业员发布正式设备档 | 没有发布角色时拒绝 |
| 跨岗账号同时有设计和品检 | 两组动作并集，但财务权限仍为空 |
