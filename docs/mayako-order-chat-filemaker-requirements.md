## 当前客户范围

自 2026-07-25 起，Mayako Orders 页面、金额汇总和订单对话统一固定使用：

`select_client_for_web_id == 0780`

并且每个查询分支同时要求：

`訂單 PO = *`

`select_client_for_web_id` 是 `出貨單` 基础表字段。它目前没有放在 `@mayako`
布局上作为返回字段，因此不会对客户显示，但 FileMaker Data API 可以正常把它
作为 find 条件。应用从登录账号的 Web 客户 ID 读取该值；Mayako 为 `0780`，
不再依赖 `shipmentCompanyId` 或公司 UUID。

2026-07-25 正式数据验收：新条件加 PO 非空返回 2 条；当天旧公司 UUID 加
PO 非空也返回 2 条。产品/零件仍继续使用各自原有的 `CU638` 范围。

## 应用侧验收要求

- 每个 FileMaker find 分支都必须包含登录账号 Web 客户 ID 的精确条件；Mayako 为 `select_client_for_web_id == 0780`。
- 出货单列表、汇总和对话查询都必须同时包含 `訂單 PO = *`，只统计和返回客户 PO 非空的记录；`出貨單 PI` 与内部订单号只能作为内部检索资料，不能对客户显示，也不能让无 PO 记录进入结果总数。
- Orders 页面与对话使用同一日期、状态和排序口径：未明确日期字段的年月/范围查询使用订单日期 `日期`；只有明确说“出货日期 / shipped date”时才查询 `出貨日期`；Shipped 要求 `出貨日期` 非空（FileMaker 查询值 `*`），Not Shipped 要求该字段为空（查询值 `=`）；默认按 `訂單 PO` 降序。
- 日期范围、状态、单号、客户 PO、物流、追踪号、包装/付款状态、客户名称和产品字段都只在 `@mayako` 布局查询。
- 返回给客户的内容仅包括已批准字段；隐藏搜索字段可以匹配，但不自动回传内部数据。
- metadata、分页和排序必须稳定；任何新增字段都要先加入 `@mayako`，再加入应用白名单。
