# FileMaker 与 Web 客户字段核对（2026-09-23）

范围：产品客户群报价所用的客户目录。只读检查线上 FileMaker DMS 与 PostgreSQL；未修改客户、报价或同步配置。此报告不等于产品、订单全库字段审计。

## 结论

- 当前字段不一致：Web `pm_reference/customers` 只有 `value/code/name/label`，实际承接来源客户 ID、客户代码、客户简称 3 项信息；`name` 和 `label` 来自同一个简称。
- 客户 OData 记录当前返回 134 个业务字段（排除 `@id/@editLink` 协议信息）。客户相关布局中已确认其中 47 个字段的类型：45 个普通字段、2 个计算字段。其余 87 个不能仅凭名字判定为计算/汇总。
- FileMaker `客戶` 共 956 条，Web 803 条；按现有导入条件合格的 803 条 ID、代码、简称全部一致，无新增或变更差异。153 条因简称为空被现有代码过滤；其中 149 条的 `公司` 字段非空。所有来源记录均能取得客户 ID，全表存在 1 组重复客户代码。
- Web 目录更新时间为 2026-09-22 21:36:09 +08:00，是导入快照，并非持续同步。
- 采用字段白名单，不追求旧系统所有字段一一复制；财务统计、旧界面辅助字段不属于本次客户/报价维护范围。

## 同步建议

1. 稳定身份使用原生客户 ID；客户代码保留前导零，重复代码进入异常清单，不能自动合并。
2. 首期补入客户自己的公司、分类、国家/地区、地区、业务负责人、默认币种、联系人、电话、邮箱、网站、地址、备注。所有这些具体字段已在 `客户资料_Edit` 确认是普通字段。默认币种不用于推断历史缺失报价币种，不自动换汇。
3. 简称为空的 153 条保留来源记录并标为资料不完整。显示时可明确使用公司/代码作兜底，不覆盖来源空值，不因为能显示就自动判为有效报价客户。
4. `審核/status/use/expiredDate` 等先保留来源含义；不能直接当成 Web 启用状态。`Role/privilege/權限ID` 不直接授予 Web 用户权限。
5. FileMaker 单向同步客户资料；Web 报价仍独立维护。按原生客户 ID 更新，先预览变化与冲突，缺失记录不自动删除；报价修改历史中的客户名称快照继续保留。
6. 目前客户代码 024 的现有主档名称与 MYA0027B1 历史报价名称不一致。增加客户同步不会自动解决身份疑点；该条报价应继续待核对，不能根据同名或代码直接改绑。
