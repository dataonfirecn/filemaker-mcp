## 原因与修复范围

`ProductMasterPage.tsx` 的预览加载逻辑只接受 PNG、JPEG、WebP、GIF 和 PDF。BMP、MPO 被排除，2 份 WMF 的 MIME 为 `application/octet-stream`，也不会发起预览请求，图片槽位可能一直显示“载入中…”。因此，仅验证对象存在或摘要正确不足以宣称页面图片全部正常。

用户确认的处理范围：不转换 BMP、MPO、WMF，不另行处理原文件，只在 UI 说明无法预览的原因。图片槽位显示具体格式不支持提示，点击“查看说明”可阅读完整原因并下载原文件；文档行也显示格式说明。加载失败与图片解码失败分别提示，不再无限显示“载入中…”。原始文件、资产身份、历史及回写映射保持不变。

## 测试边界

在生产容器中运行独立测试进程，使用线上路由实现，通过 ASGI 发起产品及资产 HTTP 请求，读取真实 PostgreSQL 和 COS。数据库连接强制只读；FileMaker Data API、OData 客户端替换为一调用即失败的哨兵，同时只允许配置的 COS 主机执行 GET/HEAD，阻止其他 HTTP 请求。

全部详情返回的资产 ID、字段、重复位置均与关系表逐项核对。每份资产经页面使用的 `/api/product-master/products/{product_id}/assets/{asset_id}` 接口读取，核验字节数和摘要。缺失产品及不存在的资产返回 404，不回退到 FileMaker。字段选项、客户搜索及产品列表也通过。

测试注入了有产品读取权限的上下文，不覆盖登录认证流程，也不是逐个产品的浏览器视觉检查。结论限于当前产品 Web 数据与资产读取链路，不代表订单等所有业务接口均不使用 FileMaker。
