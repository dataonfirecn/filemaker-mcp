# 客户主档同步

FileMaker `客戶` → Web PostgreSQL，单向同步；报价、产品、订单均不回写。与 `貿易客戶` 分开。

## 数据范围

保留原生客户 ID，并同步 19 个经 `客户资料_Edit` 验证的普通文本字段：代码、简称、公司、分类、国家/地区、地区、四位业务负责人、币种、联系人、联系人邮箱、两支电话、网站、出货地址、办公地址、备注。原始空值保留。

`pm_customer` 保存上述基础资料、版本、来源缺失标记和异常。`pm_customer_sync` 保存每次变化的完整前后快照。现有 `pm_reference/customers` 只发布名称、代码、ID、待完善标签及可选状态，不发布联系方式。

计算、汇总、全局、权限、未经核实的状态字段不在同步白名单中。客户的默认币种不用于补全历史报价币种或自动换汇。

## 异常处理

- 简称为空：公司/代码作显示兜底，标记待完善；原始简称不填造。
- 代码为空或重复：保留独立原生 ID，标记待完善，不自动合并。
- 来源记录缺失：保留旧资料和关联，标记来源缺失，不删除。
- 上述异常客户不能新加到报价；已存在的报价成员可保留或移除，历史快照不改写。
- 来源 ID 缺失/重复、字段定义变化、扫描不完整、两次扫描不一致、Web 预览后变化，均中止本次同步。
- 整个来源为空时中止，避免把所有客户误判为来源缺失。

## 执行

这是服务端显式执行的同步命令；本次不新增定时任务或开放客户端写接口。进入后端容器 `/app` 后执行：

```sh
python -m scripts.product_customers_sync --report /protected/customers-preview.json
python -m scripts.product_customers_sync --report /protected/customers-applied.json --apply --expected-digest <预览的digest>
```

报告含客户联系方式，目录必须限管理员访问；报告文件权限为 0600，终端只打印摘要。先核对客户数、异常清单、19 个字段的变更，再按摘要应用。

应用前再次检查字段类型及两轮全量读取，并校验预览摘要；事务同时提交客户主档、目录及同步历史。重试已应用摘要不会重复写入；没有变化时不增加版本。不同扫描基于同一旧快照并发应用时仅一个成功。

原产品导入脚本在该来源已有客户同步历史后，保留新客户目录，避免用旧三字段目录覆盖。原有客户搜索 URL、权限检查和分页契约保持兼容，新增字段只扩展选项信息。

## 回退

停止执行同步命令即可冻结来源同步。客户主档和同步历史保留。应用镜像可恢复上一版本，但旧报价代码不识别客户待完善标志，因此回退期间继续保持报价写入关闭。不得用旧备份覆盖已产生的新客户或报价修改；需要目录回退时先核对最新版本，再使用同步历史恢复。

## 验证

隔离 PostgreSQL 测试覆盖预览不写入、摘要不一致、重复执行、并发冲突、事务回滚、缺失来源保留、重复代码、空简称、字段类型变化及联系方式不进入搜索目录。产品和报价回归共 90 项通过。浏览器回归验证待完善客户禁选、报价操作、历史、冲突、平板布局和管理员 Tab；前端生产构建通过。
